## UI KIT — обязательная дизайн-система проекта

- Для всех новых и изменяемых веб-интерфейсов этого проекта используй UI KIT из
  `assets/brand-ui/`. Версия фиксируется в `assets/brand-ui/tokens.json`.
- Перед UI-изменениями прочитай корневой `DESIGN.md`, затем
  `assets/brand-ui/DESIGN.md` и раздел подключения `assets/brand-ui/README.md`.
  Используй skill `use-ui-kit`, если установлен; при его отсутствии следуй тем же документам.
- Сначала ищи готовый компонент в `assets/brand-ui/examples/` и документации модуля.
  Сохраняй классы, токены, состояния и доступность; затем составляй из них экран.
- Не создавай альтернативную систему кнопок, полей, карточек, цветов или шрифтов.
  Если компонента нет, расширяй систему на существующих токенах. Необходимые отличия
  по явным требованиям владельца запиши в корневой DESIGN.md с причиной.
- Короткие настройки, фильтры, действия и метаданные размещай в одну строку, пока они
  помещаются с обычными интервалами. Ширина — по содержимому; для подписанных controls
  используй brand-control-row. Не делай равные широкие колонки или полные строки без
  необходимости. Перенос — по доступной ширине контейнера, с сохранением читаемости,
  высоты controls и touch targets. Ширину полей ввода выбирай по ожидаемым данным.
- Проектные стили храни отдельно после ui-kit.css. Не редактируй generated tokens.css/js;
  значения меняй в tokens.json с генерацией. Не смешивай файлы разных выпусков.
- Подключай реальные данные и обработчики в коде приложения. Демо callbacks не являются
  рабочей отправкой. При замене DOM соблюдай BrandUI.destroy/init из документации.
- Проверь изменённые страницы в light/dark на 320/390/768/1440 px, клавиатуру,
  состояния и пути ресурсов. Учитывай поддержку браузеров целевого проекта.
