# Brand UI 1.5.2

Общая дизайн-система для PHP/HTML и других веб-проектов. Основа веб-компонентов: Bootstrap 5.3.8. Иконки: Lucide 0.468.0. Шрифты: Manrope и Oswald, сохранены локально.

Исходники: [interdizdev-stack/UIKIT](https://github.com/interdizdev-stack/UIKIT)
(приватный репозиторий). Состояние поставки и GitHub-подключения — в [ROADMAP.md](ROADMAP.md).

[Подробный аудит UX/UI от 31 октября 2026](docs/ux-ui-audit-2026-10-31.md)
содержит инвентаризацию, сравнение готовых систем, измерения, предложения по
компактным/мобильным вариантам и план развития. Текущий статус реализации и
следующая задача — в [ROADMAP.md](ROADMAP.md).

Размеры controls согласованы по шкале 36/44/52 px. Контейнер
`data-ui-density="compact"` включает компактную плотность; вложенный `default`
возвращает обычную. [Живой автономный пример](examples/density.html) и
[правила размеров](docs/foundations.md) показывают формы, меню, данные и рост текста.

[Базовые композиции](examples/patterns.html): page header/toolbar, группы действий
и выбора, summary/server errors, просмотр записи, copy и фильтры с draft/apply.
Правила подключения и API — [docs/patterns.md](docs/patterns.md).

[Мобильные данные и панели](examples/mobile.html): table/list/auto с общим выбором,
узкие контейнеры, sheets, multiselect и responsive dialog. [Контракт](docs/mobile.md).

Готовые страницы: [рабочая область](examples/workspace.html),
[вход и служебные состояния](examples/access.html), [контентный сайт](examples/content.html).
Сценарии, callbacks и перенос — [docs/pages.md](docs/pages.md).

Каталог разделён на основы, компоненты, композиции и страницы: 86 полных
копируемых документов. Preview управляет темой, плотностью, viewport, контейнером,
применимым состоянием и длинным текстом. [Покрытие и выбор](docs/system-coverage.md).

## Быстрый старт после клонирования

```sh
git clone https://github.com/interdizdev-stack/UIKIT.git
cd UIKIT
```

Для клонирования приватного репозитория нужен GitHub-аккаунт с доступом к нему.
После клонирования откройте [index.html](index.html) в браузере: каталог и
автономные примеры работают через `file://`. Установка пакетов, сборка и доступ
к CDN не нужны: CSS, JavaScript, шрифты, изображения и зависимости уже в репозитории.

Для просмотра по HTTP при наличии Python 3:

```sh
python3 scripts/serve.py
```

Откройте [http://127.0.0.1:8083/](http://127.0.0.1:8083/). Остановка сервера —
`Ctrl+C`; другой порт задаётся через `--port 8084`. Node.js нужен только для
генераторов и проверок разработки. PHP не требуется для каталога: те же HTML-компоненты
подключаются в PHP-шаблоны без отдельного адаптера.

## Подключение

Скопируйте из клона `vendor/`, `assets/`, `tokens.css`, `ui-kit.css`, `ui-kit.js`
и необходимые дополнительные модули в каталог ресурсов проекта, например
`/assets/brand-ui/`, сохраняя структуру путей. Для готового комплекта также доступен
`ui-kit.zip`. Подключите файлы в следующем порядке:

```html
<html lang="ru" data-bs-theme="dark">
<head>
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="/assets/brand-ui/vendor/bootstrap.min.css">
  <link rel="stylesheet" href="/assets/brand-ui/tokens.css">
  <link rel="stylesheet" href="/assets/brand-ui/ui-kit.css">
</head>
<body>
  <button class="btn btn-primary brand-cta" type="button">
    Отправить заявку
    <i data-lucide="arrow-right"></i>
  </button>
  <script src="/assets/brand-ui/vendor/bootstrap.bundle.min.js"></script>
  <script src="/assets/brand-ui/vendor/lucide.min.js"></script>
  <script src="/assets/brand-ui/ui-kit.js"></script>
</body>
</html>
```

Тема задаётся атрибутом `data-bs-theme="light"` или `data-bs-theme="dark"`. Его можно установить на `html` либо на отдельный контейнер. Префикс `--ui-` используется для наших токенов; стандартные классы Bootstrap сохраняются. Глобальные базовые стили Bootstrap влияют на HTML страницы, поэтому подключение к существующему сайту нужно проверить на его экранах.

`BrandUI.init(container)` обновляет компоненты в указанной области после добавления разметки через AJAX. Перед заменой содержимого вызовите `await BrandUI.destroy(container)`. Меню, диалоги, вкладки и раскрывающиеся блоки используют стандартные API и атрибуты Bootstrap.

Ссылки и семантические классы Bootstrap используют цвета текущей темы. Для акцентного
текста используйте `text-primary`: в светлой теме он получает тёмный читаемый оттенок
лайма, а `bg-primary` и основная кнопка сохраняют яркий фирменный фон.

Модули `ui-kit-forms.js`, `ui-kit-theme.js`, `ui-kit-table.js`, `ui-kit-components.js`, `ui-kit-inputs.js`, `ui-kit-feedback.js` и `ui-kit-patterns.js` подключаются после
ядра по необходимости. Весь API, зависимости и события описаны в
[docs/api.md](docs/api.md). Общая форма требует `data-brand-form` или явного init;
отправка данных подключается обработчиком проекта. Темы поддерживают light/dark/system.
Модуль компонентов управляет image/fallback аватаров, выбором и удалением chips,
а также панелями с `data-brand-drawer`. Карточки, списки и статичные теги используют CSS.
Tooltip/popover инициализируются ядром; их содержимое вставляется как текст.
Для stepper подключите модуль форм перед модулем расширенных полей. Поиск/select и
файлы сохраняют нативные значения для FormData; отправку и серверную проверку добавляет проект.

## Правила использования

- Копируйте полный HTML нужного примера из каталога и подключайте указанные для него
  модули. `catalog.css`, `catalog.js` и демонстрационные callbacks нужны каталогу;
  продуктовые страницы используют общую библиотеку и обработчики своего приложения.
- Короткие настройки, фильтры, действия и метаданные держите в одной строке, пока
  помещаются их содержимое и стандартные интервалы. Используйте `brand-control-row`
  или `brand-filter-fields`, ширину по содержимому и естественный перенос. Не задавайте
  коротким полям равные широкие колонки и полную строку по умолчанию.
- Используйте общие токены и размеры; `data-ui-density="compact"` задаёт компактную
  плотность контейнера. При переносе сохраняйте читаемые подписи, высоту controls
  и доступную область нажатия. Проверяйте ширину контейнера, обе темы и длинный текст.
- Сохраняйте семантический HTML, подписи полей, уникальные `id`, связь `for`/ARIA,
  клавиатурный фокус и текстовые сообщения состояний. Мобильное поведение выбирайте
  по содержимому: таблица, список, drawer или sheet — [docs/mobile.md](docs/mobile.md).
- После вставки динамической разметки вызывайте `BrandUI.init(container)`, перед
  заменой — `await BrandUI.destroy(container)`. Не добавляйте повторные обработчики
  поверх поведения библиотеки; зависимости и события — [docs/api.md](docs/api.md).
- Меняйте токены в `tokens.json` и запускайте генератор. Проектные дополнения храните
  в отдельном CSS после библиотеки. Сохраняйте локальные зависимости, исходные ресурсы
  и лицензии; статус собственного кода — [docs/license-status.md](docs/license-status.md).

Визуальные правила системы — [DESIGN.md](DESIGN.md), поддержка браузеров и известные
ограничения — [docs/support.md](docs/support.md).

## Выпадающие списки

Все одиночные `select.form-select` автоматически получают единый раскрывающийся список из `ui-kit.js`: фон, отступы, выбранный пункт, наведение и фокус задаются общей темой, одинаково в формах, диалогах и панели свойств. Разметка остаётся обычной:

```html
<label class="form-label" for="time">Удобное время</label>
<select class="form-select" id="time" name="time" required>
  <option value="">Выберите время</option>
  <option value="morning">10:00–12:00</option>
  <option value="afternoon">12:00–15:00</option>
</select>
```

Исходный `select` хранит значение, участвует в отправке формы, проверке `required` и сбросе формы. При выборе возникают стандартные события `input` и `change`. Компонент поддерживает клавиатуру (стрелки, Home/End, Enter, Space, Escape, Tab и поиск по первым буквам), подписи, сообщения об ошибках и недоступные пункты. Для добавленных через AJAX полей вызовите `BrandUI.init()`. После программного изменения `select.value` вызовите `BrandUI.init()` или отправьте событие `change`.

Единый список используется также у контролов каталога/preview, размера иконок и
количества строк таблицы. Выбранный пункт имеет акцентный текст и галочку; наведение
и клавиатурный фокус — фон и тонкую акцентную рамку. Наведение не меняет значение.
Searchable select/multiselect/autocomplete используют те же состояния и chevron;
для них подключите ui-kit-inputs.js и атрибуты из [docs/inputs.md](docs/inputs.md).
Меню действий Bootstrap и результаты поиска также выделяют hover/focus рамкой.

Без JavaScript используется обычный `select`. Поля с `multiple`, `size` больше 1 или атрибутом `data-native-select` сохраняют нативное поведение.

Эти атрибуты можно менять после инициализации: компонент возвращает нативный select
и его исходные атрибуты доступности. После снятия ограничения вызовите `BrandUI.init()`.
Меню временно размещается в `body`, чтобы его не обрезали scroll-контейнеры; цвета
берутся из темы исходного поля. Прокрутка страницы и resize закрывают меню.

## Телефонные поля

Каждое поле телефона размечайте как `type="tel" data-tel-input inputmode="tel" autocomplete="tel"`. Маска на основе телефонного скрипта входит в общий `ui-kit.js` и автоматически работает во всех таких полях, включая формы, добавленные через AJAX, диалоги и поля после переключения способа связи. Повторно подключать обработчики не требуется. `BrandUI.init()` также форматирует уже заполненные телефонные поля; динамические значения форматируются при фокусе и вводе.

```html
<label class="form-label" for="phone">Телефон</label>
<input class="form-control" type="tel" data-tel-input inputmode="tel"
       id="phone" name="phone" autocomplete="tel" required
       placeholder="+7 (900) 000-00-00"
       pattern="(?:\+7|8) \([0-9]{3}\) [0-9]{3}-[0-9]{2}-[0-9]{2}|\+[0-9]{7,16}">
```

Для отдельного поля `data-phone-format="none"` выключает маску;
`data-phone-format="international"` включает плюс и цифры без российских разделителей.
Глобальные настройки доступны через `BrandUI.phone.configure`; подробности в API.

Номера, начинающиеся с `7`, `8` или `9`, форматируются как `+7 (900) 123-45-67` или `8 (900) 123-45-67`, максимум 11 цифр с кодом страны. При вводе `9` код `+7` добавляется автоматически. Остальные номера сохраняются в виде `+` и до 16 цифр, как в исходном скрипте. Вставка удаляет посторонние символы из вставляемого текста, редактирование сохраняет положение курсора, а Backspace и Delete пропускают разделители маски. Значение поля при отправке содержит отформатированный номер; нормализацию и проверку на сервере выполняет подключающий проект.

В PHP используйте те же HTML-шаблоны. Проверка браузером не заменяет проверку на сервере. Обработчик отправки, защита от CSRF и сохранение данных относятся к подключающему проекту.

## Модальные окна и Lightbox

Раздел «Модальные окна» содержит информационный диалог, подтверждение действия и форму с телефонной маской и проверкой обязательных полей. У каждого примера доступны открытие, просмотр и копирование HTML. Окна используют обычные атрибуты Bootstrap `data-bs-toggle="modal"`, `data-bs-target` и `data-bs-dismiss="modal"`, общий стиль, закрытие по Escape, удержание фокуса и возврат к кнопке открытия.

Раздел «Lightbox» содержит галерею с подписями, счётчиком, переключением кнопками и стрелками клавиатуры. Просмотр входит в `ui-kit.js`; подключите Bootstrap перед ним и добавьте атрибуты к обычным ссылкам на изображения:

```html
<a href="/images/photo-1.jpg" data-lightbox data-lightbox-group="project"
   data-lightbox-caption="Первое изображение">
  <img src="/images/photo-1-thumb.jpg" alt="Первое изображение">
</a>
<a href="/images/photo-2.jpg" data-lightbox data-lightbox-group="project"
   data-lightbox-caption="Второе изображение">
  <img src="/images/photo-2-thumb.jpg" alt="Второе изображение">
</a>
```

Одинаковый `data-lightbox-group` объединяет ссылки в галерею. Без группы открывается только выбранное изображение. Подпись берётся из `data-lightbox-caption` или `alt` вложенного изображения. Ссылки, добавленные через AJAX, работают автоматически. Без JavaScript или Bootstrap ссылка открывает оригинал изображения. Программный API: `BrandUI.lightbox.open(linkElement)` и `BrandUI.lightbox.close()`.

Смена изображений сопровождается плавным затуханием, небольшим смещением в направлении переключения и изменением высоты области просмотра. Длительность берётся из токена `--ui-motion-normal` (180 ms). Следующий кадр загружается и декодируется перед переходом; при быстрых нажатиях показывается последний выбранный кадр. Закрытие отменяет ожидающую загрузку и анимацию. Настройка `prefers-reduced-motion: reduce` отключает переход.

Автономная страница `examples/overlays.html` работает без каталога и сервера. Её `overlays.js` содержит HTML примеров и демонстрационные обработчики подтверждения и результата формы. Общую проверку и состояния предоставляет `ui-kit-forms.js`; при переносе формы подключите этот модуль и замените демонстрационный onSubmit интеграцией проекта. Изображения примера сохранены в `assets/gallery/` и включены в ZIP.

## Cookie И Яндекс Метрика

Три варианта уведомлений: нижняя полоса (`bar`), компактный блок в углу (`corner`), модальный диалог (`modal`). В каждом доступны принятие всех cookie, отказ от аналитики и отдельное окно настроек. Яндекс Метрика по умолчанию выключена; закрытие окна не считается согласием.

Подключите `cookie-consent.js` после `ui-kit.js`. Готовый HTML можно скопировать из раздела «Cookie и Метрика»; замените ссылку на реальную политику вашего проекта. Компоненты с `data-cookie-consent` инициализируются автоматически. Для динамического HTML вызовите `BrandUI.init()`.

Либо создайте компонент через API:

```js
const host = document.getElementById('cookieHost');
host.innerHTML = BrandUI.cookies.markup({
  id: 'siteCookies',
  variant: 'bar',
  policyUrl: '/privacy/cookies/',
  storageKey: 'my-project-cookie-consent'
});
const cookies = BrandUI.cookies.init(host.firstElementChild, {
  onChange: function (consent) {
    // Only load your analytics integration when consent.metrica is true.
    // On revocation, stop it and clear its cookies according to your integration.
  }
});
document.getElementById('cookieSettings').addEventListener('click', cookies.settings);
BrandUI.init();
```

API: `cookies.settings()` открывает настройки; `cookies.getConsent()` возвращает выбор или `null`; `cookies.destroy()` отключает компонент. Событие `brand:cookie-consent` содержит `detail.consent` и `detail.storageAvailable`; оно возникает при сохранённом выборе и после решения посетителя. Не подключайте счётчик заранее: UI-компонент не может блокировать уже установленную Метрику или удалить её сторонние cookie. Подключение, остановка счётчика и серверные журналы согласий остаются ответственностью проекта.

Выбор сохраняется в localStorage текущего origin на 180 дней (настраивается через `maxAgeDays`). При недоступном хранилище выбор действует до перезагрузки. В каталоге все действия используют `persist: false` и не сохраняют согласие для самого каталога. Сам счётчик нигде не загружается.

Автономный рабочий пример: `examples/cookies.html`. Варианты: `?variant=corner` и `?variant=modal`. Пример сохраняет только выбор, не подключает аналитику и содержит пояснение о фактической обработке данных. Тексты являются шаблонами, не гарантией соответствия законодательству. Проверьте их и интеграцию под конкретный сайт.

Описание cookie и данных сверено с официальными страницами: [cookie Метрики](https://yandex.ru/support/metrica/ru/general/cookie-usage), [данные счётчика](https://yandex.ru/support/metrica/ru/code/data-collected).

## Токены

`tokens.json` — исходные значения цвета, темы, типографики, отступов, скруглений и движения. После изменения запустите:

```sh
node scripts/build-tokens.mjs
```

Команда обновляет `tokens.css` и `tokens.js`. Node.js нужен только для этой операции разработки. Готовые CSS и JS работают на обычном статическом или PHP-хостинге.

Для мобильных приложений используйте значения из `tokens.json` с преобразованием единиц и шрифтов под выбранную платформу. Нативные компоненты пока не реализованы.

Токены используются в стилях самой библиотеки и каталога. Правила типографики,
компоновки, состояний и тем описаны в [docs/foundations.md](docs/foundations.md).
Автономный пример: `examples/foundations.html`.

Генератор проверяет структуру и диапазоны значений. Проверка актуальности без записи:

```sh
node scripts/build-tokens.mjs --check
node tests/tokens.mjs
```

## Визуальное направление

Основная палитра: чёрный, белый, лайм `#C1F000`. Заголовки: плотный Oswald; основной текст: Manrope. Радиусы: 4–8 px. Состояния ошибок, успеха, предупреждения и информации имеют отдельные семантические цвета.

Цвета и шрифты — стартовая интерпретация предоставленных изображений, а не извлечённые оригинальные бренд-токены. Название Brand UI временное. Исходные изображения сохранены в assets/references; переиспользуемая SVG-графика для готовых блоков находится в assets/graphics. Правила — в [site-blocks.md](docs/site-blocks.md); обычные элементы управления используют спокойные поверхности.

## Состав

- `ui-kit.css`, `ui-kit.js`: общая тема и инициализация.
- `ui-kit-forms.js`, `ui-kit-theme.js`, `ui-kit-table.js`: переносимые формы, переключение темы и таблица.
- `ui-kit-components.js`, `ui-kit-inputs.js`, `ui-kit-feedback.js`, `ui-kit-patterns.js`: базовые компоненты, расширенные поля, обратная связь и композиции.
- `cookie-consent.js`: варианты cookie-уведомлений и управление выбором.
- `tokens.json`, `tokens.css`, `tokens.js`: исходные и готовые токены.
- `vendor/`: закреплённые версии библиотек и их лицензии.
- `assets/fonts/`: локальные шрифты и лицензии OFL.
- `assets/gallery/`: локальные изображения для примера lightbox.
- `assets/references/`: пользовательские исходные изображения.
- `examples/`: автономные примеры форм, компонентов, таблицы, обратной связи, блоков сайта, cookie и галереи.
- `catalog.css`, `catalog.js`, `catalog-examples.js`, `index.html`: рабочий каталог с полным копированием примеров.
- `docs/`, `DESIGN.md`, `integrations/`: документация, визуальные правила и шаблоны подключения в проекты.
- `scripts/`: локальный сервер, генераторы токенов/иконок/шрифтов и выпуск архивов.
- `tests/`: проверки ресурсов, поведения, доступности и визуальные эталоны.

Исходное дерево репозитория — основная поставка: после клонирования ничего не требуется
извлекать из ZIP. Дополнительный `ui-kit.zip` содержит общую библиотеку, токены,
документацию, автономные примеры, графику и лицензии. `ui-kit-catalog.zip` дополнительно
содержит каталог, исходные референсы, генераторы, тесты и визуальные эталоны.

## Разработка и продолжение работы

Текущие этапы, задачи и результаты проверок записаны в [ROADMAP.md](ROADMAP.md).
История изменений — [CHANGELOG.md](CHANGELOG.md). Перед продолжением разработки
прочитайте текущую точку продолжения в карте.

Браузерные регрессионные проверки требуют Node.js 22+ и установленный Chrome:

```sh
node tests/browser.mjs
node tests/inputs.mjs
node tests/feedback.mjs
node tests/data-gallery.mjs
node tests/site-blocks.mjs
node tests/catalog.mjs
```

Проверка запускает отдельный временный профиль и сервер на localhost. Результат
сохраняется в `test-results/browser.json`; этот каталог исключён из Git.
Путь к Chrome можно задать переменной `UIKIT_CHROME`.

Сборка и проверка обоих архивов (Node.js и Python 3, без установки пакетов):

```sh
python3 scripts/build-release.py
```

Сборочные и браузерные проверки входят в полный архив каталога. При загрузке на
обычный HTML/PHP-хостинг нужны только готовые файлы библиотеки.

Проверка ссылок автономных HTML и актуальности ресурсов в ZIP после сборки:

```sh
python3 tests/static.py
```

Расширенные данные: [таблица](docs/table.md) и [галерея](docs/gallery.md).

Блоки сайта: [примеры](examples/site-blocks.html), [компоновка и графика](docs/site-blocks.md).

Каталог: [полное копирование, iframe, поиск и иконки](docs/catalog.md), [подключение](index.html#integration).
