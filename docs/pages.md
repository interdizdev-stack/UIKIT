# Готовые страницы

Три автономных рецепта работают через HTTP и file://. Их исходный HTML и обработчики
доступны также в разделе каталога `#pages`. Они используют общие компоненты; новый
обязательный runtime приложения не добавляется. `examples/pages.js` — код примеров,
который переносится и адаптируется вместе со страницей, а не универсальный backend SDK.

| Пример | Сценарии |
|---|---|
| [workspace.html](../examples/workspace.html) | Header/sidebar, независимый main scroll, список/детали/создание/редактирование, настройки и опасная зона |
| [access.html](../examples/access.html) | Вход, восстановление, 403/404, ошибка сервиса, отсутствие соединения и retry |
| [content.html](../examples/content.html) | Сайт услуг, каталог материалов с поиском/фильтрами, статья, FAQ и форма связи |

## Рабочая область

Оболочка `brand-app-shell` занимает 100dvh, sidebar и main прокручиваются независимо.
До 992 px sidebar становится общим offcanvas с focus trap/Escape. Header позволяет
выбрать тему и плотность области. Внутри используются Manrope, обычные controls,
один заголовок текущего экрана и одно главное действие.

Таблица использует table/list/auto. Переход в детали не пересоздаёт таблицу:
поиск, страницы и selection сохраняются. Создание и редактирование обновляют один
массив rows; массовое действие меняет тот же источник. Нет скрытой второй модели.
Loading/error/retry задаёт общий controller таблицы. `onLoad` возвращает новые строки
с уникальными ID и обновляет модель деталей тоже.

```js
BrandUIPageExamples.setup(container, {
  async onSave({ id, values, signal }) {
    // Приложение сохраняет запись и проверяет signal.
    // Серверная ошибка: return { errors: { name: 'Название уже занято' } };
    return { row: { id: id || 'ID-ОТ-СЕРВЕРА', ...values } };
  },
  async onSettings({ values, signal }) { /* сохранение профиля */ },
  async onLoad({ signal }) { /* return [{id,name,status,description}, ...] */ },
  async onBulk({ selected, signal }) { /* отметить выбранные готовыми */ }
});
const page = BrandUIPageExamples.get(container.querySelector('[data-page-example]'));
page.configure({ onSave });
page.table.setState('error', 'Сервис временно недоступен.');
```

Без callbacks данные меняются только в памяти этой вкладки. Одинаковые названия
проектов возвращают inline/server summary. Callback может вернуть `{errors,message}`
или `{row}` с подтверждённым ID/данными; throw показывает error и оставляет введённое.
Проверка прав, настоящая сеть, маршруты и хранение относятся к подключающему приложению.

У каждой формы есть снимок сохранённых значений. Input/change показывает «Есть
несохранённые изменения», reset возвращает снимок. При уходе dirty guard открывает
общий modal с отменой и явным отказом от правок; beforeunload включает нативное
предупреждение браузера после реального взаимодействия. Его текст определяет браузер.
Отправка блокирует повторный submit. Правки, введённые во время callback, сохраняются
как новый черновик; успешный ответ обновляет только отправленный снимок. Reset/destroy
отменяет запрос, поздний ответ не меняет данные. Подтверждения очищаются даже при
destroy во время открытия, вместе с backdrop и блокировкой body.

Опасная зона сбрасывает только демонстрационные данные после подтверждения. Для
реального удаления замените действие и текст с точным описанием последствий.

## Доступ и контент

Access показывает шесть законченных состояний с понятным следующим действием.
`onLogin({formData,signal})`, `onRecovery({formData,signal})`, `onRetry({signal})`
подключают приложение. Ошибка возвращается через общий forms controller; успешный
callback входа очищает password. Пример не создаёт сеанс и не пишет пароль в storage.
Смена экрана отменяет незавершённое действие; callback должен соблюдать AbortSignal.
Фактические тексты ответа восстановления выбирайте без раскрытия наличия аккаунта.

Content собирает существующие hero/services/cases/FAQ и один контактный сценарий.
Все anchors ведут к существующим секциям. Фильтры применяются явно, есть no-results
и сброс; статья возвращает фокус на исходное действие. `onContact(args)` получает
контракт общего forms controller. Без него результат прямо сообщает, что заявка
не отправлена. Фото, условия, реквизиты и факты заменяются материалами проекта.

## Перенос и проверка

Bootstrap CSS → tokens.css → ui-kit.css; затем Bootstrap Bundle/Lucide, ядро и
нужные модули из полного HTML. Content использует examples/site-blocks.js. Не
подключайте catalog.css/catalog.js в приложении. При повторении меняйте prefix/ID.
`await BrandUI.destroy(root)` очищает формы, таблицу, sidebar, подтверждения и события;
после вставки вызовите setup. До глобальной замены токенов смотрите DESIGN.md.

Сохранённые проверки pages.mjs покрывают 16 сочетаний оболочки, сохранение и ошибки,
конкурирующие правки, переходы/подтверждения, очистку открытого modal, доступ,
контент и offline. Результаты и границы браузеров — [support.md](support.md).
