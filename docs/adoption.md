# UI KIT в других проектах

Для принятого UI KIT используйте три слоя: правило проекта в AGENTS.md, описание
дизайна в [DESIGN.md](../DESIGN.md) и переносимый
[skill use-ui-kit](../integrations/skills/use-ui-kit/SKILL.md).
AGENTS.md закрепляет обязательное применение, skill помогает выбрать и подключить
компоненты, DESIGN.md объясняет визуальные решения. DESIGN.md нужно явно указать
в инструкциях: произвольное имя документа не делает его автоматически загружаемым правилом.
Наличие skill тоже не гарантирует его вызов в каждой задаче.

Механика загрузки — официальные документы
[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) и
[skills](https://learn.chatgpt.com/docs/build-skills). Инструкции помогают агенту;
приёмка страниц остаётся проверкой результата. Более конкретные инструкции и явные
требования владельца могут изменить решение.

## Подключить новый HTML/PHP-проект

1. Распакуйте актуальный ui-kit.zip в `assets/brand-ui/` проекта. Сохраняйте структуру
   vendor/assets/examples/docs. Полный ui-kit-catalog.zip удобен для локального выбора
   компонентов; библиотечный архив достаточен для интеграции.
2. Добавьте содержимое [AGENTS.project.md](../integrations/AGENTS.project.md) в корневой
   AGENTS.md проекта. Это фрагмент: существующие инструкции сохраняются. Замените путь,
   если ресурсный каталог другой. Не копируйте AGENTS.md разработки исходного UI KIT.
3. Создайте или дополните корневой DESIGN.md проекта записью ниже. Если такой файл уже
   есть, согласуйте источники и зафиксируйте отличия, не перезаписывая существующий дизайн.
4. Для repo-scoped skill скопируйте папку
   `assets/brand-ui/integrations/skills/use-ui-kit/` в `.agents/skills/use-ui-kit/` проекта.
   Она должна содержать SKILL.md. Такой skill переносится вместе с Git проекта.
5. Подключите CSS/JS по [README](../README.md#подключение) и выбирайте готовые
   [примеры](catalog.md). Для PHP используйте тот же HTML в общих шаблонах/layout.

Пример записи в **корневом DESIGN.md подключающего проекта**:

```md
# Дизайн проекта

Дизайн-система: UI KIT.
Путь библиотеки: assets/brand-ui/.
Версия при подключении: 1.5.2; фактическая версия — assets/brand-ui/tokens.json.
Правила дизайна: assets/brand-ui/DESIGN.md.
Подключение и API: assets/brand-ui/README.md и assets/brand-ui/docs/api.md.
Проектные стили: assets/css/project.css, после ui-kit.css.
Отличия от UI KIT: отсутствуют. Новые отличия записывать с причиной и областью действия.
```

Пример команд **из корня нового проекта**, когда папок назначения ещё нет:

```sh
mkdir -p assets/brand-ui .agents/skills
unzip /home/hp/UIKIT/ui-kit.zip -d assets/brand-ui
cp -R assets/brand-ui/integrations/skills/use-ui-kit .agents/skills/
```

Команды приведены для этой машины; на другой укажите путь к своему ZIP.
Не распаковывайте поверх изменённой копии библиотеки и не перезаписывайте существующий
skill: сначала сравните версии. Веб-URL ресурсов может отличаться от пути на диске
(например, public/assets в PHP-проекте); явно укажите оба пути в проектных документах.
В file:// примерах оставляйте относительные пути, как в существующих examples.

После установки начните новый сеанс Codex в проекте и проверьте, что он видит
AGENTS.md, путь UI KIT и skill. Если skill не появился, перезапустите Codex.
Пример задачи: «Используй $use-ui-kit. Собери страницу заявки по DESIGN.md проекта,
на готовых компонентах UI KIT, с реальным обработчиком нашего приложения».

## Сделать правилом на этой машине

Для всех своих проектов можно установить skill в пользовательскую папку skills.
Актуальная документация указывает `~/.agents/skills/`; в окружениях с настроенным
`~/.codex/skills/` используйте подтверждённый каталог своего клиента.
Не устанавливайте две копии с одинаковым именем. Переносимость между компьютерами
лучше обеспечивает repo-scoped вариант выше.

В глобальный `~/.codex/AGENTS.md` (или AGENTS.md в настроенном CODEX_HOME) можно добавить:

```md
Для новых веб-проектов по умолчанию используй мой UI KIT из /home/hp/UIKIT.
Перед реализацией интерфейса прочитай его DESIGN.md и README.md; используй use-ui-kit.
Подключай конкретный выпуск локально в проект и фиксируй путь/версию в его DESIGN.md.
В существующих проектах сохраняй принятую дизайн-систему, если я явно не поручил миграцию.
Явные требования проекта имеют приоритет над этим значением по умолчанию.
```

Это локальный путь владельца, не публичная зависимость. Наличие исходного каталога
нужно проверять; работающий проект получает собственную копию ресурсов.
Данная поставка содержит шаблоны, но сама не меняет глобальные настройки и другие проекты.

## Версии и расширения

Фиксируйте один выпуск библиотеки в Git подключающего проекта. Не подключайте общий
изменяемый каталог как runtime-ресурс сразу нескольких сайтов: обновляйте каждый
проект осознанно по [upgrading.md](upgrading.md) и проверяйте его страницы.
Исходный UI KIT сохранён в приватном [GitHub-репозитории](https://github.com/interdizdev-stack/UIKIT).
Запуск после клонирования и состав исходников описаны в [README.md](../README.md),
состояние синхронизации — в [ROADMAP.md](../ROADMAP.md);
npm/framework-адаптер не требуется для этой схемы. Для другого стека оценивайте
интеграцию отдельно.

Сначала готовый компонент, затем композиция, затем проектное расширение на токенах.
Короткие настройки, фильтры, действия и метаданные собирайте в одну строку по ширине
содержимого; переносите только при нехватке места в контейнере. Не задавайте им равные
широкие колонки или полную строку по умолчанию. `brand-control-row` и `brand-filter-fields`
дают такую компоновку, сохраняя размеры controls; примеры — [foundations.md](foundations.md).
Локальные классы храните в project.css, общие исправления возвращайте в UI KIT.
Изменение токенов — tokens.json и генератор, а не ручная правка generated файлов.
Сохраняйте LICENSE/OFL; статус собственного кода — [license-status.md](license-status.md).

## Проверить подключение

Проверьте отсутствие 404, порядок CSS/JS, обе темы, четыре ширины, клавиатуру,
состояния loading/empty/error/success и настоящую отправку/данные приложения.
Для AJAX: await BrandUI.destroy(container) перед заменой, BrandUI.init(container)
после вставки. Не переносите demo callbacks как рабочую отправку.
Поддержка исходного выпуска — [support.md](support.md); проверяйте браузеры аудитории проекта.

Готовые page recipes и callbacks находятся в [pages.md](pages.md). Переносите
семантический HTML и нужные обработчики в структуру приложения, заменяя демо данные.
