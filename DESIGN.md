# Дизайн UI KIT

Этот документ фиксирует существующую систему для страниц, использующих UI KIT.
Точные значения находятся в [tokens.json](tokens.json), готовая разметка — в
[примерах](examples/foundations.html), API — в [docs/api.md](docs/api.md).
Правила подключения в другие проекты — [docs/adoption.md](docs/adoption.md).
Brand UI остаётся временным названием; документ не утверждает название, знак или лицензию.

## Источники решений

Используйте готовый компонент → композицию готовых компонентов → локальное расширение
на токенах. Перед новым компонентом найдите ближайший пример и проверьте его состояния.
Не создавайте вторую систему кнопок, полей, карточек, диалогов или уведомлений.
Явные требования владельца проекта могут изменить систему; такие отличия фиксируются
в DESIGN.md подключающего проекта с причиной и областью действия.

Численные значения меняются в tokens.json с генерацией tokens.css/tokens.js.
Этот документ описывает применение, не служит вторым источником значений.

## Визуальный язык

Нейтральные светлые/тёмные поверхности, контрастный текст, лаймовый акцент, ясная
типографическая иерархия и умеренный рисованный декор из assets/graphics.
Акцент выделяет главное действие, выбранное состояние и значимый фрагмент;
не окрашивайте им весь текст или каждую поверхность. Основное действие использует
`btn btn-primary`, второстепенное — соответствующий outline/secondary-вариант из примеров.

| Задача | Использовать |
|---|---|
| Фон / поверхность / поле | `--ui-bg`, `--ui-surface`, `--ui-field` |
| Основной / вторичный текст | `--ui-text`, `--ui-muted` |
| Акцентная заливка / текст | `--ui-color-accent` / `--ui-accent-text` |
| Граница блока / поля | `--ui-border` / `--ui-border-control` |
| Статусы | `--ui-success`, `--ui-warning`, `--ui-danger`, `--ui-info` и соответствующие классы |
| Размеры и интервалы | `--ui-space-*`, `--ui-radius-*`, `--ui-control-*`, `--ui-icon-*` |

Для семантических поверхностей и текста берите токен текущей темы, а не hex или
палитру другой темы. В light `text-primary` использует читаемый тёмный оттенок акцента;
яркая заливка primary сохраняется. Цвет ошибки сопровождается понятным сообщением.

## Типографика и компоновка

Manrope — основной текст и интерфейс, Oswald — крупные заголовки. Шрифты локальны.
Используйте роли `brand-display`, `brand-h1`…`brand-h6`, `brand-body`, `brand-small`,
`brand-ui`, `brand-caption`; HTML-уровень заголовка выбирайте по структуре документа.
Размеры micro/meta/catalog-* предназначены для каталога, не для основного текста сайта.
Для рабочих экранов используйте `brand-page-title` и `brand-panel-title` на Manrope;
`brand-number` даёт выровненные цифры, `brand-code` — моноширинный текст.
Oswald сохраняется для крупной сайтной и фирменной типографики.

`data-ui-density="compact"` на контейнере согласованно уменьшает controls, интервалы,
строки и меню. `default` возвращает обычную плотность во вложенной области. Текст
controls остаётся 14 px (редактируемый текст при coarse pointer — минимум 16 px).
Явные `btn-sm/lg`, `form-control-sm/lg`, `form-select-sm/lg`
и `input-group-sm/lg` задают минимумы 36/52 px; обычный control — 44 px, компактный —
36 px. Длинный текст и подписи переносятся по ширине контейнера; при coarse pointer
цели controls, подписи выбора, range, tabs и закрытие overlays имеют минимум 44 px.

`brand-container` ограничивает ширину, `brand-reading` — длинный текст,
`brand-section` — отступы секций, `brand-grid--2/3/4` — сетку,
`brand-stack` — вертикальный поток, `brand-cluster` — строку с переносом,
`brand-surface` — стандартный блок. Bootstrap grid/utilities также доступны.
Сетка учитывает собственную ширину; для данных в узком контейнере доступны общие
table/list/auto и мобильные панели — [docs/mobile.md](docs/mobile.md).
Обычная поверхность использует границу без обязательной тени; тень обозначает
подъём overlays. Не обрамляйте каждую вложенную группу отдельной карточкой.
Не меняйте ширины, отступы и радиусы каждого блока независимо от шкалы.
Конкретные размеры и адаптивные правила — [docs/foundations.md](docs/foundations.md).

Короткие связанные настройки, фильтры, действия и метаданные размещайте в одну строку,
пока их ширина по содержимому и стандартные интервалы помещаются в контейнер.
Для подписанных controls используйте `brand-control-row`, для действий — `brand-cluster`;
`brand-filter-fields` следует тому же правилу. Не растягивайте короткие selects на равные
широкие колонки и не задавайте отдельную полную строку без необходимости. Переносите
целые элементы только при нехватке фактической ширины контейнера, сохраняя порядок.
Ширину полей свободного ввода выбирайте по ожидаемой длине данных; растяжение поиска
или длинного поля должно иметь конкретную причину. Сохраняйте читаемые подписи, размер
текста и высоту controls; компактная раскладка не уменьшает touch targets.

## Компоненты и состояния

Берите исходный HTML из examples или каталога, до инициализации JavaScript.
Сохраняйте классы, data-атрибуты, labels, имена полей и структуру доступности.
При повторении блока меняйте ID и связанные for/aria/anchors.
`catalog.css` и `catalog.js` относятся к просмотру библиотеки.

- Поля: нативные input/select с `form-control`/`form-select`; общий JS добавляет поведение.
  Для поиска, multiselect и stepper используйте [docs/inputs.md](docs/inputs.md).
- Карточки, списки, аватары, chips, навигация и drawer — [docs/components.md](docs/components.md).
- Таблица — [docs/table.md](docs/table.md); состояния и уведомления — [docs/feedback.md](docs/feedback.md).
- Секции сайта выбирайте по задаче посетителя, сохраняя одно главное действие в секции;
  композиция и графика — [docs/site-blocks.md](docs/site-blocks.md).

Предусматривайте применимые hover/focus/active/disabled, loading, empty, error и success.
Фокус клавиатуры виден; loading не допускает повторную отправку; ошибка даёт следующий
шаг. Не объявляйте успешную отправку без результата обработчика приложения.

## Темы, иконки и графика

Тема задаётся `data-bs-theme="light"`/`"dark"` на html или контейнере;
light/dark/system переключает ui-kit-theme.js. Проверяйте обе темы, включая overlays.
Lucide берите из vendored набора: полный lucide.min.js либо подходящий subset, один
файл за раз. Декоративным иконкам задавайте aria-hidden, кнопкам без текста — имя.

Мазок, стрелка, рамка, точки и текстура — существующие `brand-graphic` варианты.
Декор не перекрывает текст/контролы и не передаёт обязательную информацию.
Не придумывайте логотип на основании этих материалов. Фото, реальные отзывы и
показатели предоставляет проект; демонстрационные данные заменяются.

## Расширение и готовность страницы

Проектный CSS подключайте после ui-kit.css, используя отдельные классы проекта и
существующие токены. Общие исправления компонентов возвращайте в исходный UI KIT
и переносите проверенным выпуском. Не редактируйте generated tokens.css/tokens.js.
Изменение бренда или новый технологический стек оформляется отдельным решением;
готового framework-адаптера текущая HTML/PHP-поставка не обещает.

Страница готова после проверки 320/390/768/1440 px, light/dark, клавиатуры,
состояний данных, загрузки локальных ресурсов и фактического сценария приложения.
Не должно быть горизонтальной прокрутки документа; таблица может иметь свою область.
Учитывайте reduced motion и forced colors. Проверенные среды и ограничения —
[docs/support.md](docs/support.md); браузеры аудитории проекта проверяются отдельно.
